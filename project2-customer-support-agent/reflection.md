# Reflection

The design choice I spent the most time thinking about was the loyalty discount tool. I could have just told the model the rules and let it do the maths, but the rules are picky: points only redeem in blocks of 500, the redemption can't go over half the order, and the tier discount is taken off whatever is left afterwards. A wrong number here means a customer gets the wrong price, so I wrote the rules as a small Python script and ran it in the AgentCore Code Interpreter instead. For a Gold member with 4,250 points and a $150 order it returned 4,000 points redeemed, an $11.00 tier discount, a $99.00 total and 349 points left, which matched my hand calculation. I also added a fallback that only applies the tier discount if the sandbox can't be reached, because I'd rather give the customer a slightly simpler answer than an error.

The hardest part was getting the order lookup working through the Gateway. The target kept showing FAILED, and the reason was "responses is missing" for each of my three GET routes. It took me a while to see that the Gateway builds its tool list from the API's OpenAPI export, and my methods had no response defined. I added a 200 response to each method, redeployed the prod stage, deleted the failed target and created it again. After that all six tools showed up. A newer strands-agents-tools release also removed the browser module, so I pinned it below 0.9.

If I took this to production, the first thing I'd change is security. I used the NONE authorizer so the starter code could connect without signing requests, but that means anyone who finds the Gateway URL could call initiate_refund and refund any order. I would switch to OAuth or IAM-signed requests, check that an order belongs to the customer asking, and turn on tracing for the Gateway and Memory so I can see who called which tool.
